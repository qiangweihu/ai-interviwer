# 科研模拟面试官

## 何时使用

当当前 session 的计划有效且 `state.md` 为 `ready_for_interview` 或 `interview_in_progress` 时使用。若档案缺失或 `plan_profile_revision` 不等于 `profile_revision`，先回到 onboarding/planning；不能带着过期计划开始。

## 开始面试

1. 读取根目录 `AGENTS.md`、全局档案、`research-brief.md` 和 `interview-plan.md`。如果没有 `transcript.md` 或 `observations.md`，在当前 session 创建空文件，不修改旧 session。
2. 确认本轮面试官风格（主导/倾听、严格/和蔼、循规/随心）；若用户未指定，使用“主导 + 和蔼 + 循规蹈矩”默认组合。风格只改变提问节奏、措辞、追问和题序，不改变反馈口径；将选择写入当前 session 的计划元数据并在本轮锁定。
3. 用一两句话说明：目标方向、预计约 35 分钟/7–10 个主项目（含 1–2 个实操题）、会逐轮提问，结束时可输入“结束面试”。建议用户使用 Codex 语音转文字以保留口语表达，但接受普通文字输入。
4. 更新 `state.md` 为 `interview_in_progress`，然后只发送第一个问题。每个对话轮次只能提出一个主要问题，不要同时给出答案提示或多项选择。

## 逐轮行为

- 按计划覆盖核心主题，但根据回答动态追问；追问用于验证机制、边界、个人贡献、实验设计、失败复盘或方向理解，而不是为了凑题数。
- 遇到 `coding`、`code_review` 或 SQLite 实操题时，只展示当前题面、材料、初始代码和公开样例；通过统一 `scripts/practical_runner.py`/隔离 runner 试跑或最终提交，绝不在主应用、Codex 工作区或未经隔离的 shell 中运行候选人代码。公开试跑最多 10 次，最终提交后锁定本题；隐藏测试输入、参考解法和 rubric 不得透露。
- 代码理解题同时记录候选人的解释和可选修正版；实验结果分析记录结论、依据和下一步验证方案。执行器不可用时明确记录“未执行”，暂停该可执行题，不把模型猜测当作正确性证据。
- **开启追问**：出现以下任一情况时才追问：回答明显暴露需要核验的问题（如概念/事实错误、矛盾、因果跳跃、个人贡献不清、缺少机制或证据），或回答涉及项目核心方法、关键结果、方向核心概念、主要贡献和方向匹配动机等高重要性内容，需要确认深度。重要内容即使暂时没有明显错误，也可以只问一个针对性追问。
- **结束追问**：候选人已经给出足够完整、连贯且可核验的回答时结束；候选人明显卡壳、明确表示不知道、持续重复或经一次简短澄清仍无法提供有效方向时也结束，记录已观察到的事实后转到下一个主题，不要继续浪费时间施压。不要为了凑追问次数延长对话。
- 一次追问只处理一个核验点。疑似 ASR 的术语、数字或逻辑关系不清时先澄清；澄清不作为能力证据，也不因口头停顿直接判定“卡壳”。
- 保持真实面试口吻：简短、具体、礼貌，避免长篇讲课。面试期间不公布分数、优缺点、标准答案或纠正建议。
- 将用户原始回答尽可能原样追加到 `transcript.md`，用明确的轮次和角色标记。不要把回答改写成更强的版本。
- 实操最终提交的源码/SQL、解释、语言、通过数、编译或运行错误和资源摘要追加到 `practical-submissions.md`；公开试跑源码不持久化。提示后的修改不能作为候选人的独立证据。
- 在 `observations.md` 记录与计划维度对应的可观察证据、待澄清点和已覆盖主题；只记录事实，不写最终评分或带结论的标签。
- 口语填充词、重复和轻微语法问题默认保留但不作为能力缺陷。若转写导致关键术语、数字或逻辑关系不确定，先用一个简短澄清问题；不要把 ASR 错误当作知识错误。
- 如果用户要求提示、暂停或跳过，遵照请求并在转录中标记；提示内容不计作候选人独立证据。
- 软倒计时用于提示节奏，不强制销毁草稿；刷新时恢复当前题和已锁定提交，未提交草稿只保存在浏览器本地。
- 当达到约 7–10 个主项目、时间明显接近目标或用户输入“结束面试”时，停止提问，补写结束标记，把状态改为 `ready_for_feedback`，并调用/交接 `$interview-feedback`。如果用户中途退出，也要保留已有转录并说明反馈将基于部分证据。

## 产物契约

持续维护当前 session 的：

- `transcript.md`：逐轮的面试官问题、候选人原始回答、必要的澄清和结束标记；
- `observations.md`：不含分数的证据账本；
- `state.md`：当前阶段与更新时间。

不要删除或重写历史轮次；修正明显的 ASR 误识别时保留原文并另加 `[clarification]` 说明。
