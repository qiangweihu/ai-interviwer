# 科研面试反馈

## 何时使用

当当前 session 已结束并存在 `transcript.md` 时使用，通常状态为 `ready_for_feedback`。不要在面试进行中提前评分；不要将本 skill 用作录取决策、心理诊断或普通简历评价。

## 前置检查

1. 读取根目录 `AGENTS.md`、全局档案、当前 `research-brief.md`、`interview-plan.md`、`transcript.md` 和 `observations.md`。
2. 如果转录为空或只有极少证据，明确标记 `evidence_limited`，只反馈已观察到的内容；不要用猜测填补空白。
3. 区分候选人实际表达、简历事实、面试官提示和疑似 ASR 噪声。提示后的答案不能作为独立能力证据。

## 输出要求

写入 `.interview/sessions/<session-id>/feedback.md`，默认使用简体中文，至少包含：

1. **总体结论**：本轮表现概览、证据覆盖范围和信心说明，不做录取/淘汰判断。
2. **五项 1–5 分评价**：专业基础、项目深度、科研思维、方向匹配、表达沟通。每项都要引用对应回答轮次或简历事实；证据不足时标记低信心，不为了完整而虚构分数依据。
3. **优势**：2–4 条，说明具体行为和为什么有价值。
4. **主要问题**：按影响排序，分别标记为知识、推理、项目真实性/深度、方向理解、表达或疑似转写问题，并给出原回答证据。
5. **回答改进示例**：针对最重要的 1–3 个问题，给出结构化答题思路或简短示例；不得捏造候选人没有做过的经历和数据。
6. **三个优先训练动作**：每项写练习目标、具体操作、完成判据。
7. **下一轮建议**：从本轮薄弱维度选择下一次应增加的主题或追问，并保留可复用的全局档案。

不要因口头语、停顿、重复或已确认的 ASR 错误过度扣分；表达评价只针对影响理解的组织、准确性和回应问题的程度。

## 收尾

更新 `state.md` 为 `complete` 并记录 `feedback_session`、`updated_at`。向用户先展示反馈摘要，再提供完整文件位置。用户说“再练一轮”时交还给 `$interview-planner` 或 `$mock-interviewer` 创建新 session，不覆盖本次反馈。
